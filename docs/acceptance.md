# 骨架检查与真实版本验收

## 本机演示走查

1. npm ci、npm run dev:h5；首页只有四栋房子，底部只有广场/消息/我的；各入口能打开。
2. 搭子小屋找到小林的电影计划，进详情→相近计划；只推荐小桃的电影计划，不推荐小禾散步。
3. 邀请小桃→底部我的→切换小桃→消息→接受。再切小林确认目标满员；小桃原计划已关闭。不会自动确认。
4. 切小林→二手台灯详情→联系→留言；消息入口找到会话，原商品链接能返回详情。切小桃可查看并手动回复；不存在自动假回复。
5. 失物详情→联系同样进入共用消息。点任意作者名称进入其公开主页，看各模块发布，不会进入“自己的家”。
6. 发布二手/失物/搭子/技能互助，返回列表并搜索；收藏与举报有明确结果。重启后文本演示数据保留；临时图片不承诺永久。
7. 切换身份后不能修改别人的发布、看不属于自己的会话或通知。生产权限仍需后端实现。
8. H5 点击接收匹配通知显示站内消息替代说明；微信模板未配置时显示待配置，不伪造发送成功。
9. npm run check、npm test 和两个 build 均通过。

## A 第一阶段专项（10 月 20 日前）

1. 用 320px、390px 手机宽度与桌面打开广场：底图保持完整，二手、搭子、失物、自己的家四个招牌均可见且可点；消息在底部。点击四个入口应进入对应页面。
2. 点击步道，标记“你”的豆豆沿路抵达并停下；点建筑/树岛时选择最近步道点，不穿过中心树岛。移动途中重新指定目标、暂停/继续和回到起点均可操作。离开广场停止场景计时；滚动页面后点按目标仍对应正确位置。H5 开启减少动态效果时初始暂停。
3. 搭子列表选“电影”看到两个种子计划，选“散步”看到一个；叠加不存在的关键词显示空状态，重置后恢复。状态可切换招募中/满员/完成/关闭；不能混入不符合条件的记录。
4. 发布一条搭子计划，填日期、开始结束时间、人数与自定义完整类别（例如羽毛球）。返回列表输入同一类别可以找到，类别首尾空白不影响新发布的查询。跨页仍使用同一组条件；只编辑而未搜索的新关键词/类别不能影响“加载更多”。
5. 进入技能求助，发布一条 Python 求助；Python 筛选能查到。自己的详情标记完成后，“求助中”查不到、“已完成”能查到；返回搭子入口正常。
6. 广场本人计划点“找时间合拍的人”，只出现小桃电影计划。发出邀请后看到等待确认和“查看邀请进度”；进入消息，不能替对方接受。切换演示身份为小桃后手动接受，目标计划满员 2/2、来源计划关闭。重置演示后分别走查拒绝、发送者取消，状态准确。

## 首版真实业务（另外验收）

- 两个账号、两台设备真实登录，互看公开主页；所有列表、详情、状态来自真实后端。
- 清空本机存储不删除后端发布；换电脑能查到；图片存储和权限有效。
- 同校同类同日严格时间重叠才推荐；过期、满员、已经加入其他计划被排除。

- 会话参与者权限正确，保留原内容链接；原内容删除/失效时显示明确提示。
- 完成状态、取消和失物归还遵守真实权限；举报管理仅管理员访问。
- 微信真机/H5 都能走通核心流程；老师能打开公网 H5 URL。
