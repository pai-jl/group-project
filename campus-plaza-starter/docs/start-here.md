# 第一天下午怎么合作

1. 一个人把本包解压内容放进团队 GitHub 仓库，提交 package-lock.json；把真实姓名写入 docs/collaboration.md。
2. 三个人 clone，统一 Node 版本，运行 npm ci 和 npm run dev:h5。每个人都看到四栋房子再开始分工。
3. 先按 docs/acceptance.md 走一遍本机演示流程，理解计划与计划匹配、邀请方向、主页和消息关联。
4. A 从广场和搭子页面开始；B 从二手和账号开始；C 从失物和消息开始。不要各写一套登录或消息中心。
5. 共同确定后端（课程允许 CloudBase；本包未绑定 SDK）、登录方式、开发环境及权限。B 维护请求接入，模块负责人实现自己业务。
6. 把需要实现的接口与 docs/interfaces.md 对齐，先接列表/发布/详情，再接权限、邀请确认和消息。先让数据可以在两台设备之间同步。
7. 每天收尾合并小 PR，运行四项检查。不要等第一周最后一天才第一次合并。

骨架接口是“大家知道怎么调用 + 调用文件已存在”。不等于负责人已经写完全部真实业务。

## 建议首周里程碑

| 时间 | 交付 |
| --- | --- |
| 第 1 天 | 三台电脑能跑；统一 AppID/环境；登录和部署路线明确 |
| 第 2～3 天 | 真实二手、失物、搭子发布查询；公共主页、上传接入 |
| 第 4～5 天 | 推荐规则、邀请确认和消息贯通，服务端权限/事务校验 |
| 第 6 天 | 两端人工验收；完成 H5 部署并验证可访问 URL |
| 第 7 天 | v0.1 固定演示，修复问题，记录第二周扩展 |

第二周再安排订阅通知、主题活动、技能/求购匹配。拍照估价、更多装扮不进入首版承诺。
